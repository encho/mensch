# Harmony Chord Engine (Isolated Namespace)

This document is the quick re-onboarding guide for the new isolated harmony chord engine.

Purpose:
- Keep harmonic identity, inversion, voicing, and foreign bass as separate concepts.
- Provide deterministic MIDI note resolution.
- Fail hard on invalid or unsatisfiable specs.
- Stay isolated from the legacy engine until integration is explicitly done.

---

## 1. Where The New Engine Lives

- Chord spec model: `lib/mensch/harmony/chord_spec.ex`
- Resolver pipeline: `lib/mensch/harmony/resolver.ex`
- Interactive UI lab: `lib/mensch_web/live/chord_lab_live.ex`
- Tests: `test/mensch/harmony/resolver_test.exs`

The legacy engine remains unchanged in `lib/mensch/chord_spec.ex`.

---

## 2. Conceptual Model

The new model explicitly separates four responsibilities:

1. Harmonic identity
- `root` + (`quality` or explicit `tones`)

2. Inversion
- `inversion` defines structural ordering of chord tones before voicing.

3. Voicing
- `voicing` defines register/distribution of the already inverted tones.

4. Independent foreign bass
- `foreign_bass` is not part of inversion/voicing calculations.
- It is added only after voiced chord tones are produced.

---

## 3. Data Structures

### 3.1 `Mensch.Harmony.ChordSpec`

Fields:
- `root` pitch class atom
- `quality` chord quality atom (optional if `tones` provided)
- `tones` explicit scale-degree strings (optional if `quality` provided)
- `octave` anchor octave for harmonic root
- `inversion` signed integer
- `voicing` `%Mensch.Harmony.ChordSpec.Voicing{}`
- `foreign_bass` `%Mensch.Harmony.ChordSpec.ForeignBass{}` or `nil`

### 3.2 `Voicing`

Fields:
- `type`: `:close | :open`
- `center_note`: MIDI center target (integer)
- `range_min`: optional lower MIDI bound
- `range_max`: optional upper MIDI bound
- `voice_count`: optional desired number of voices
- `doubling`: `:root | :top | :auto`

### 3.3 `ForeignBass`

Fields:
- `pitch_class`
- `octave` optional

If octave is omitted, resolver places it deterministically below the lowest voiced chord tone.

---

## 4. Resolution Pipeline

Implemented in `Mensch.Harmony.Resolver`:

1. Resolve chord tones
- Convert quality/tones into intervals and concrete MIDI notes from root+octave.

2. Apply inversion
- Rotate tones with octave correction.
- Positive inversion moves lowest tone up octaves.
- Negative inversion moves highest tone down octaves.

3. Apply voicing
- Normalize voice count.
- Apply voicing type transformation (`:close` or `:open`).
- Align result to center/range by octave shifting candidates.

4. Resolve foreign bass independently
- Validate it is truly foreign (pitch class not in chord tones).
- Resolve explicit or implicit octave.
- Enforce it stays below lowest voiced chord note.

5. Combine final notes
- Merge foreign bass (if any) with voiced chord tones.
- Return ascending MIDI notes.

Public entry points:
- `resolve/1` => final MIDI notes
- `resolve_steps/1` => intermediate stages + final notes

---

## 5. Hard-Fail Rules

The engine raises `ArgumentError` for invalid or unsatisfiable cases.

Notable hard-fail behavior:

1. Invalid chord/voicing/foreign bass structure.
2. Unsatisfiable voicing constraints.
3. `voice_count` lower than resolved tone count.
4. Out-of-range MIDI notes.
5. `foreign_bass` pitch class that is not foreign.
- If requested bass belongs to chord tones, fail hard.
- Use inversion/voicing instead.
6. Foreign bass not below lowest voiced chord tone.

---

## 6. Voicing Details (v1)

### 6.1 Supported strategies
- `:close`
- `:open`

### 6.2 Open voicing rule (deterministic v1)
- Keep the lowest voice unchanged.
- For upper voices, raise every 2nd upper voice (2nd, 4th, ...) by +12 semitones.
- Re-sort ascending.

This is intentionally simple and extensible.

### 6.3 Center/range placement
- Generate octave-shift candidates (global shifts) and keep those in valid range.
- Rank candidates by:
  1. smallest distance between median note and `center_note`
  2. smallest absolute shift
  3. deterministic tie-breaker by signed shift

---

## 7. Doubling Behavior

When `voice_count` exceeds resolved tone count, extra notes are generated by doubling.

`doubling` options:
- `:root` => duplicate root pitch class upward
- `:top` => duplicate top voice upward by octaves
- `:auto` => deterministic priority:
  1. root
  2. fifth
  3. third
  4. seventh/tensions (remaining pitch classes)

This ordering is fixed for reproducibility.

---

## 8. Foreign Bass Semantics

`foreign_bass` is independent from chord inversion/voicing.

Rules:
1. If nil, no independent bass is added.
2. If present and chord-tone pitch class => fail hard.
3. If octave present => use explicit octave.
4. If octave omitted => place below lowest voiced chord tone.
5. Respect MIDI/range constraints.

This preserves distinction between:
- inversion/slash chord using chord tones
- truly foreign bass note

---

## 9. Invariants

1. Inversion before voicing.
2. Voicing does not introduce new pitch classes unless via explicit doubling.
3. Foreign bass does not participate in inversion/voicing.
4. Deterministic output for identical input.
5. Fail hard instead of silently degrading.

---

## 10. Typical Usage

Example shape:

```elixir
alias Mensch.Harmony.ChordSpec
alias Mensch.Harmony.ChordSpec.Voicing
alias Mensch.Harmony.ChordSpec.ForeignBass
alias Mensch.Harmony.Resolver

spec =
  ChordSpec.new!(%{
    root: :c,
    quality: :maj7,
    octave: 3,
    inversion: 1,
    voicing: %Voicing{
      type: :open,
      center_note: 60,
      voice_count: 5,
      doubling: :auto,
      range_min: 36,
      range_max: 84
    },
    foreign_bass: %ForeignBass{pitch_class: :f_sharp, octave: 2}
  })

steps = Resolver.resolve_steps(spec)
final_notes = Resolver.resolve(spec)
```

## 12. Extensibility Notes

To add more voicing strategies later (for example drop voicings), keep this pattern:

1. Preserve current pipeline order.
2. Add strategy-specific transforms in voicing stage.
3. Keep deterministic tie-breaks and fail-hard semantics.
4. Extend tests before wiring into machines.

Potential next strategies:
- drop_2
- drop_3
- spread variants
- custom user-defined rules

---

## 13. Integration Reminder

Current state:
- New engine is isolated in `Mensch.Harmony.*`.
- Legacy runtime machines still use the existing chord engine.

When integrating later:
1. Define compatibility adapter defaults to preserve current behavior.
2. Add machine-level opt-in first.
3. Compare output parity sample-by-sample before global switch.
